# ASCOT5 Agent Notes

- The C simulation is in `src/`; the Python package is `a5py/`. The root Makefile moves built C binaries/libraries from `src/` to `build/`.
- Standard build: activate `ascot-env`, then `make libascot -j`, `make ascot5_main -j`, and `pip install -e .`.
- Leonardo build: load `nvhpc/25.11 hpcx-mpi/2.25.1 cuda/12.6 cmake/3.27.9 python/3.11.7 hdf5/1.14.3--hpcx-mpi--2.25.1--nvhpc--25.11`; from repo root run `srun make ACC=1 GPU=1 MPI=1 ascot5_main -j 16`. The root target places the executable at `build/ascot5_main`.
- Leonardo runtime also needs `$HOME/TorchFort/build/lib` in `LD_LIBRARY_PATH` and `$HOME/libatomic.so.1.2.0` in `LD_PRELOAD`.
- `feature/training_model` uses `config_bfield_B_dB.yaml` and the trainable TorchScript model generated by `src/bfield_autodiff_model.py`. It uses SiLU and `sin(18 phi), cos(18 phi)` for the verified 20-degree toroidal period.
- TorchFort trains 13 normalized targets: B, nine ASCOT derivative targets, and a weighted cylindrical-divergence residual. `simulate_fo_fixed.c` uses batches up to 2048, half marker states and half uniform R-Z-phi points labelled with `B_field_eval_B_dB`; this replay avoids relying only on marker-orbit coverage. NN outputs are for training/validation and do not drive particle pushing.
- The trained checkpoint is `bfield_B_periodic_dB_trained.pt`; `src/wrap_bfield_autodiff.py` restores it and converts B/gradients to physical units.
- Leonardo simulation tests run in `/pitagora_scratch/userexternal/mpeybern/test_ascot5`; run `sbatch launch_ascot.sh` there. The script copies the config, generates the initial TorchScript model, and launches `~/ascot5/build/ascot5_main`. Set `BFLD_INITIAL_WEIGHTS` to warm-start from a compatible SiLU-periodic checkpoint.
- Python unit/physics suites are `a5py/testascot/unittests.py` and `a5py/testascot/physicstests.py`; unit tests expect compiled binaries under `build/`.
